# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

SmallJ is a Smalltalk VM written in Java (derived from Timothy Budd's SmallWorld via Eric Scharff's fork), plus the Smalltalk class library, compiler and Swing-based IDE written in Smalltalk itself. There is no build system (no Maven/Gradle) and no automated test suite.

## Repository layout

- `VM/` — the Java interpreter (`VM/src/smallj/core/*.java` for the interpreter, `VM/src/smallj/objects/*.java` for `SmallObject` and its subclasses, `VM/src/smallj/compiler/` for the compiler, `VM/src/smallj/image/*.java` for image loading, saving and building). Dependencies in `VM/lib/` (Apache commons jars). Open `VM/VM.code-workspace` in VSCode.
- `Smalltalk/` — the runtime working directory: `.st` class sources in package-like subfolders, `smallj.jar` (the compiled VM), and `image.sjim` (the binary image). The jar and the image are generated by `buildJar.sh` and `buildImage.sh` and are not in git (see `.gitignore`).
- `Extension/` — VSCode syntax-highlighting extension for `.st` files; `Deploy.cmd` copies it into the local VSCode extensions folder.
- `Documentation/` — FFI reference (`ForeignFunctionInterface.md`) and project structure notes.
- `Website/` — git-ignored.

## Running and building

- Run: from `Smalltalk/`, `java --enable-preview -jar smallj.jar [imageFile] ["startup expression"]` (defaults: `image.sjim`, `"SystemBrowser show"`). `start.sh [imageFile]` does this in the background, logging to `smallj.log`. **The working directory must be `Smalltalk/`.**
- Debug the VM: the VSCode launch config in `VM/.vscode/launch.json` runs `SmallJApp` with `cwd` set to `../Smalltalk`.
- Build the VM: `Smalltalk/buildJar.sh [jarFile]` (default `smallj.jar`, overwritten only if the build succeeds) compiles the VM sources with `javac` and creates a self-contained jar that includes the classes of the libraries in `VM/lib`. The default VSCode build task (`java: exportjar:SmallJ` in `.vscode/tasks.json` / `VM/.vscode/tasks.json`) also exports `Smalltalk/smallj.jar`. After changing VM code, the jar must be regenerated, since `start.sh` runs the jar.
- Build a fresh image from sources, without an existing image: `Smalltalk/buildImage.sh [imageFile]` (default `image.sjim`, overwritten only if the build succeeds; compiles the VM sources itself, then runs `SmallImageBuilder`). The VSCode task `Build image` runs it, and is the `preLaunchTask` of `Launch SmallJApp`, so debugging always starts from an image freshly built from the `.st` sources. `Smalltalk/start.sh [imageFile]` starts SmallJ.

### Method compilation happens in Java
`SmallCompiler.java` is the only compiler; there are no compiler classes in Smalltalk. It uses `SmallParser.java` (lexer and parser, producing a tree of the node classes in `SmallNodes.java`) and then generates bytecode from that tree with `SmallEncoder.java`. It is used both by `SmallImageBuilder` (bootstrapping an image) and at runtime: `Class>>parseMethod:` calls primitive `< 47 class methodText >`, which returns a new `Method` or a `String` error message. All compiling (Save & Compile, file-in, `String>>doIt`) goes through it, so language/compiler changes are made in Java and need a rebuilt VM. The bytecodes it emits must match the operations in `SmallInterpreter`. `SmallImageBuilder.java` mirrors `ClassParser.st` (chunk format) and `Class.st` (class/metaclass layout); keep them in sync. Images built from the current sources need a VM (`smallj.jar`) that has primitive 47.
- The VM sources have no `package` declarations even though they live under `smallj/core/`, `smallj/objects/`, `smallj/compiler/` and `smallj/image/`; each folder is a separate source root (see `java.project.sourcePaths` in `Build.code-workspace` and `VM/.vscode/settings.json`, and the `javac` line in `buildImage.sh`); the launch config and export task use main class `SmallJApp`.

## Architecture

### Source-file based workflow; the image holds only compiled code
Sources live only in `.st` files; the image (`image.sjim`) holds compiled methods but no source. The Smalltalk System Browser (`Smalltalk/Gui/SystemBrowser.st`) reads the `.st` files, and "Save & Compile" / "Compile All" / "File In" recompile them via `Smalltalk/Compiler/ClassParser.st` → `Class>>compileMethod:` → `Class>>parseMethod:` → primitive 47 (`SmallCompiler.java`). Changes reach the image only when it is saved (`System saveImage`, also offered on exit). Editing a `.st` file on disk does nothing until it is compiled inside a running SmallJ. A broken image can prevent startup, so back up `image.sjim` before risky changes.

### `.st` file format
One class per file:
```
CLASS Object subclass: 'Boolean' variables: 'a b' classVariables: ''
	"Class comment: lines before the first keyword line are skipped."
CLASSMETHODS
classSelector: arg
	...
!
METHODS
instanceSelector: arg
	...
!
```
Keyword lines `CLASSMETHODS` and `METHODS` start sections of class-side and instance methods; they may toggle any number of times. Each method is a header line (selector and arguments, optionally temporaries), then the body, ending with a line containing only `!`. Blank lines between methods are allowed. The format is read by both `ClassParser.st` (file-in in a running image) and `SmallImageBuilder.java` (building an image); change them together. The System Browser jumps to a method via its `lineNum`, the line of its header.

### VM
- `SmallJApp` loads the image (`SmallImage` / `SmallImageReader` / `SmallImageWriter`) and evaluates the startup expression in `SmallInterpreter`.
- `SmallInterpreter.java` is the core. It dispatches bytecodes via the `operations[]` table of method references in `SmallOperations.java` (which works on the interpreter's current `context`), and primitives via the `primitives[]` table in `SmallPrimitives.java` (indexed by number, `maxPrimitive = 65`; also works on the interpreter's `context`). To add a primitive, register a method reference in the `SmallPrimitives` constructor and call it from Smalltalk as `< N args... >`.
- Object model: `SmallObject` and its subclasses (`SmallInt`, `SmallLong`, `SmallFloat`, `SmallByteArray`, `SmallBlock`, `SmallContext`, `SmallClass`, `SmallJavaObject`). `MethodCache` caches lookups. `SmallThread` backs block forking.

### Java FFI: how Smalltalk reaches Java
Instead of adding VM primitives for each feature, Smalltalk calls arbitrary Java through reflection primitives (registered in `SmallPrimitives.java`, reflection logic in `SmallJavaObject.java`). The main ones:
- `37` new object, `38` invoke method, `39` invoke static method
- `43`/`44`/`45` typed variants of 37/38/39, which take explicit arg types for overload resolution
- `40`/`41` read field / static field, `46` load class
- `42` hooks up event listeners to Smalltalk blocks (e.g. `< 42 self 2 block ActionEvent >`)

Example from `Smalltalk/Component/Button.st`: `< 38 nil self 'setText' text >`. Conversions: nil↔null, true/false↔Boolean, SmallInt↔Integer, String↔String, Float↔Double. Use `JavaArray` to pass arrays. Convention: wrap each Java call in exactly one Smalltalk method named after the Java method, in a Smalltalk class mirroring the Java class. The GUI library in `Smalltalk/Component/` and `Smalltalk/Event/` is built this way and closely mirrors Swing, so most new GUI features are one-line FFI methods, not VM changes. The full reference is in `Documentation/ForeignFunctionInterface.md`.

### Unit tests
Each class `X` in `Smalltalk/<Folder>/` has a test class `TestX` in `Smalltalk/<Folder>/Test/TestX.st`, a subclass of `TestCase` (`Smalltalk/Base/TestCase.st`). Its methods whose names start with `test` check results with `assert:`. Run one class with `TestX run`, all with `TestCase runAll` or the System Browser menu Class > Test All. From the GUI a failed assert opens the Debugger; from the startup expression it prints on the console and continues. Tests of GUI classes create components without showing windows and read Java state through the FFI. Arrays and fractions have no value equality, so tests compare them by `printString`.

### Smalltalk packages
`Base` (Object, Class, Block, Context, Boolean), `Collection`, `Magnitude` (numbers incl. large ints), `Compiler` (only `ClassParser`, the file-in of `.st` files), `Component` (Swing wrappers), `Event`, `Gui` (System Browser, Debugger, Inspector, editors), `Io` (File, System, PrintStream), `Java` (JavaObject, JavaArray, Semaphore).

## Conventions

- Java: tabs, spaces inside parentheses (`foo( a, b )`), braces on their own line for types and methods. Modern Java features (lambdas, method references) are encouraged.
- Smalltalk: descriptive variable names, short statements, MVC separation, tab indentation.
